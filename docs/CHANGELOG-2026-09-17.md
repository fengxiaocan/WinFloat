# WinFloat 开发变更记录

## 1. 修改概述

- 根据《Windows 轻量性能悬浮监控工具需求文档》从空目录搭建 .NET 8 WPF 应用。
- 完成性能采集、悬浮展示、系统托盘、配置持久化和常用交互设置。
- 新增 WinFloat 应用图标，并接入桌面图标和系统托盘。
- 采集线程与 UI 解耦，单项硬件传感器不可用时不会阻断其他指标。

## 2. 需求来源

### 用户需求

根据需求文档设计开发一个 Windows 轻量性能悬浮监控程序。

### 目标结果

提供 Windows 10/11 x64 的轻量悬浮面板，显示下载/上传、CPU、内存、GPU 和可用的温度信息，并支持托盘、置顶、穿透、位置保存、多显示器和基础设置。

## 4. 核心实现说明

### 修改前

仓库只有需求文档，没有可运行项目、源码或配置。

### 修改后

应用采用 `C# + .NET 8 + WPF`。后台 `MonitorService` 按配置周期采样，UI 线程只接收最新 `MonitorSnapshot` 并更新文本。网络使用网卡累计字节数差值，CPU 和内存使用 Windows 原生 API；GPU 使用率和温度由独立硬件模块读取。

### 为什么这样实现

- WPF 适合无边框、置顶、DPI 和多显示器悬浮窗口。
- 原生 CPU/RAM/网络采集不需要抓包驱动或管理员权限。
- 硬件传感器独立封装，读取失败时可以安全降级。
- 配置保存使用 JSON，避免数据库和持续写盘。

### 为什么没有采用其他方案

- 没有引入网络抓包、过滤驱动或系统服务，避免扩大权限和资源开销。
- 没有实现进程级监控、历史曲线、FPS 注入、超频和复杂硬件页面，以保持 MVP 的轻量定位。

## 5. 关键函数说明

### `MonitorService.RunAsync`

- 作用：按用户设置周期执行采样并发布快照。
- 输入：刷新周期、网卡和 GPU 选择等配置。
- 输出：`MonitorSnapshot` 事件。
- 调用关系：由 `App` 启动，调用 CPU、内存、网络和硬件采集器。
- 注意事项：单次异常会记录后继续下一次采样。

### `NetworkMonitor.Read`

- 作用：计算选定网卡的实时上下行速度。
- 输入：网卡 ID 或 `Auto`。
- 输出：上下行字节/秒和选中的网卡。
- 调用关系：由 `MonitorService` 每个采样周期调用。
- 注意事项：只保留最近 3 个样本做轻量平滑。

### `HardwareMonitor.Read`

- 作用：读取 GPU 使用率和 CPU/GPU 温度。
- 输入：GPU 名称或 `Auto`。
- 输出：硬件快照；无法读取时返回空值。
- 调用关系：由 `MonitorService` 调用，UI 不直接访问硬件库。
- 注意事项：温度不可用不会影响 CPU、RAM、网络指标。

## 6. 配置变更

- 新增 `%LOCALAPPDATA%\WinFloat\config.json`，保存窗口位置、布局、主题、监控项目、刷新率、网卡/GPU 选择等。
- 新增用户级注册表启动项 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\WinFloat`。
- 无系统服务、驱动、数据库或云端配置。

## 7. 影响范围分析

### 直接影响

新增 WinFloat 桌面程序及其本地配置目录。

### 间接影响

启用开机启动后会增加当前用户的启动项；启用 LibreHardwareMonitor 传感器后会按采样周期读取硬件传感器。

### 风险点

- 温度传感器是否可用取决于主板、显卡驱动和权限，程序会降级隐藏温度。
- 当前运行时尚未做长时间功耗、不同厂商硬件矩阵和全屏游戏兼容性测试。

### 兼容性

目标为 Windows 10/11 x64，普通用户权限运行；未实现 ARM64 构建。
